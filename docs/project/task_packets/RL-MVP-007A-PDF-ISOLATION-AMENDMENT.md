# RL-MVP-007A PDF isolation planning amendment

Status: owner-approved for documentation publication only. NOT APPROVED for implementation. Epoch E0045.

Supersedes inconsistent PDF-processing security language in RL-MVP-007A-PORTABLE-FOUNDATION.md. Users may submit self-selected PDFs including sensitive and manually redacted material, without an allowlist. Uploaded means accepted for bounded validation, not necessarily processable. The initial 25 MiB and 100-page operating limits remain. Unsupported inputs must not generate guessed targets or scores. Processing restricted research data still requires relevant institutional permission.

Preferred proposed isolation: a dedicated rootless Podman Linux arm64 virtual machine on macOS Apple Silicon, with no shared host directories, no network, no secrets, no artifact or database mounts, nonroot read-only disposable worker containers, bounded resources and 60-second timeouts. Verify the isolation on a clean second Mac and ensure offline operation after separately approved installation. This is not protection against a hypervisor or kernel compromise. Podman installation, images, machine setup, dependency downloads and running code are NOT authorized by this publication.

Verified trust-interface blocker: RunStore.ingest_redacted_pdf calls derive_prediction_source, which executes PDF target detection and canonicalization on host PDF bytes. Its validate_prediction_source only checks structural consistency; it does not prove an external parser's result originates in PDF bytes. A future worker bridge must avoid host PDF reparsing and must not trust caller-supplied source records. It must bind actual input hash, project and role, deterministic document/target identity, strict bounded output schema, worker image/protocol provenance and host-verified isolation. If this cannot preserve Task 4 source authority, STOP. Existing Task 3 reference parsing and Task 6 evaluation cannot be extended to arbitrary reference PDFs without separately approved isolation work. DEC-022 synthetic truth remains unchanged.

Proposed future scope extends 007A foundation files with modifications to src/redaction_lab/store.py, src/redaction_lab/prediction_source.py, tests/test_worker.py, tests/test_prediction_source.py; creates src/redaction_lab/application/isolation.py, src/redaction_lab/application/worker_protocol.py, tests/application/test_isolation.py, tests/application/test_worker_protocol.py, tests/security/test_pdf_worker_container.py, packaging/pdf-worker/Containerfile, packaging/pdf-worker/containers.conf, packaging/pdf-worker/runtime.lock, packaging/pdf-worker/README.md, .containerignore, scripts/build-pdf-worker.sh, scripts/verify-pdf-worker.sh, uv.lock, and .python-version. This is proposed file scope, not permission to edit. pyproject.toml and additional Task 3/6 files require fresh authorization if necessary.

Testing design: isolation canaries for inaccessible host files and network, no VM volume shares, runtime and image digest checks, kill/limits, bounded output and forged-identity refusal, reference separation, artifact crash recovery, five-table migrations, Task 4/6 regressions and clean recipient Mac restart and offline checks. FileVault can be required for sensitive storage but is not institutional data permission. No implementation, downloads, inference, private-data use, costs, deployment, Task 7B/C/P/D, or scientific approval follows from this amendment.
