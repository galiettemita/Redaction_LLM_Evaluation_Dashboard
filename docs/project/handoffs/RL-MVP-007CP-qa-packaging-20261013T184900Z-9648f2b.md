## QA / security findings

### Static-path confinement — PASS

The loader walks install-root components descriptor-relatively with `O_DIRECTORY|O_NOFOLLOW`, then verifies final package/dist/asset directories and opens leaves no-follow.

Static files are:
- bounded to 4 MiB each / 8 MiB aggregate / 32 entries;
- exact-name constrained to `index.html` and hashed-looking JS/CSS asset paths;
- regular, same-user, non-group/world-writable, single-link files;
- exact-size and SHA-256 matched to manifest.

Unexpected extra files, dotfiles, directories, symlinks, hardlinks, FIFO/nonregular files, writable files and identity changes fail frontend verification.

No user-controlled request path becomes a filesystem path.

### Same-origin / loopback routing — PASS

The launcher binds only `127.0.0.1`.

Static requests reuse the existing API loopback/origin validator and additionally require Host to equal the literal listening port.

API requests under `/api/v1` are delegated unchanged to the reviewed 7B API, preserving its Host/Origin/body rules.

No CDN/external static route exists.

### HTTP framing — PASS by source boundary

`QuietHandler.parse_request` rejects:
- duplicate Host;
- duplicate Origin;
- duplicate Content-Length;
- duplicate Content-Type;
- any Transfer-Encoding.

This closes the ambiguity that WSGI would otherwise normalize away.

Static WSGI handling also rejects query/raw-target mismatch and nonzero request bodies.

The selected server remains a local diagnostic standard-library HTTP stack, not a production HTTP-hardening claim.

### API delegation — PASS

The static layer does not parse or reinterpret API payloads for `/api/v1`; it delegates directly to the existing API callable.

No new prediction, reference-trust, scoring or worker authority path exists in static hosting.

### Security headers / browser loading — PASS

Static responses include:
- CSP default-deny;
- `script-src 'self'`;
- `style-src 'self'`;
- `connect-src 'self'`;
- object/base/form/frame restrictions;
- X-Frame-Options DENY;
- nosniff;
- no-referrer;
- restrictive Permissions-Policy;
- no-store.

The reviewed Frontend build uses local hashed JS/CSS, so this policy is compatible with the intended artifact layout.

### Symlink / replacement defenses — PASS

Parent components, dist/assets directories and leaf assets are opened no-follow.

Directory/file identity is rechecked around verification.

Verified bytes are retained in memory, so later leaf replacement/symlink redirection cannot alter served contents until restart.
