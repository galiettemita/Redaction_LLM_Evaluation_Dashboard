## Observed blocking defects

### High / blocking — Target IDs collide across projects

`_target_for_rectangle` hashes:
- `redacted_document_version_id`
- page index
- normalized bbox
- detector version

but **not `project_id`**. Because IDs are explicitly project-scoped in the project contracts, the same local document-version label and geometry in two projects produces the same `target_id` and `target_version`. The RL-MVP-002 QA packet explicitly requires preventing target-ID collisions across projects/document versions.

This does not by itself prove a cross-project authorization bypass, because records also carry `project_id`, but it violates the required identity invariant and creates avoidable ambiguity for downstream caches, logs, idempotency keys or stores that treat target IDs as identifiers.

Required correction: include the project scope in identity derivation or formally define/test a composite identity that cannot be confused with a globally unique target ID. Publish regression coverage for same PDF/version/geometry under distinct projects.

### High / blocking — Ambiguous multi-column layouts are accepted instead of failing closed

The task packet requires visible word/line/page order to be preserved and ambiguous layouts to fail closed. The detector has no multi-column/layout-ambiguity classifier. A normal two-column page using black upright text, no images/annotations/line art and an ordinary black overlay satisfies the current detector's supported checks.

The canonicalizer then sorts character/marker events by top coordinate and x coordinate, grouping same-y events into a line. For two columns this yields row-major interleaving, not a reliable source reading order. The independent reproduction returned:
`LEFT1 RIGHT1\nLEFT2 RIGHT2`.

This is not merely formatting: it changes model-visible context order and therefore the experiment input. The implementation must either recognize and preserve an approved deterministic column order or fail such layouts as UNSUPPORTED for the week-one boundary.

### High / blocking — Overlapping rectangles can become multiple targets for one visually contiguous redaction region

DEC-007 defines one visually contiguous blacked-out region covering text as one immutable target. The candidate iterates every filled near-black rectangle and independently appends a target whenever it overlaps text. There is no check for rectangle overlap, union/contiguity, or ambiguous duplicate coverage.

An independent synthetic PDF probe confirmed pdfplumber surfaces two overlapping filled rectangles separately and both can cover the same text. Under the reviewed loop, both satisfy the target path. That can yield two markers/targets for one visually contiguous black region and can duplicate or split the same underlying hidden span.

Required correction: for overlapping/intersecting vector rectangles, either deterministically fuse only when they are proven to represent one physical region or fail closed as ambiguous. Add explicit overlap regressions. Adjacent non-overlapping physical boxes must remain distinct.

## Positive findings

Within the inspected narrow subset, several important controls are present:

- canonicalization has no reference input and re-runs detection against the same source hash/project/document identity before accepting a supplied DetectionResult;
- any character with positive geometric intersection with a target box is removed entirely from canonical text, which is conservative for partial-glyph overlap;
- visible target text is replaced with deterministic markers and the canonicalizer checks exactly one generated marker per target;
- rotated pages/text, nondefault crop boundaries, images/annotations, transforms, clipping/graphics-state operators, optional/marked content, invisible text modes, non-black text visibility ambiguity, non-black occlusions, line/table art near text, nonrectangular shapes in text flow, uncertain paint order, multiline target coverage, malformed PDFs and no-visible-text pages are rejected or marked unsupported;
- black artwork far from text is distinguished from text redaction;
- adjacent non-overlapping boxes have dedicated regression coverage;
- the hidden selectable-text trap is explicitly removed from canonical/model-manifest text in the candidate tests;
- parser error messages are intentionally suppressed/sanitized instead of returning source-bearing exception text;
- no reference, model/provider, scoring, database, UI, deployment, cloud or paid-call path is present in the reviewed implementation.

These positives do not cure the three identity/layout/contiguity failures above.
