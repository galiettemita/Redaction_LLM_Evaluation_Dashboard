## Review result

CHANGES_REQUESTED before Research can clear RL-MVP-001 truth/scoring semantics for integration. This is not scientific validation and does not approve D03-D06.

### Blocking findings

1. **CONFIRMED truth is under-constrained.** ReferenceMapping.enforce_truth_availability() requires only nonblank exact_revealed_text when status=CONFIRMED. The schema currently permits CONFIRMED with reference_document_version_id=None, reference_token_locator=None, redacted_canonical_hash=None, reference_canonical_hash=None, global_alignment_version=None, and empty left/right anchor evidence. That is insufficient for DEC-010/011 and INTERFACES.md, which require exact truth tied to a specific reference/version and alignment evidence.
   - Contract-level fix: a CONFIRMED mapping must require the reference document version, exact revealed text, exact token/span locator, both canonical-version/hash bindings, alignment/mapping method version, and explicit alignment evidence. If a target is legitimately at a document boundary, represent boundary evidence explicitly rather than treating missing anchor evidence as equivalent to confirmed alignment.
   - Alignment-service responsibility: uniqueness/reliability itself is established by the alignment algorithm, but the persisted contract must make the evidence needed to substantiate CONFIRMED mandatory.

2. **A VERIFIED EvaluationRecord can be constructed without proving confirmed truth or a successful prediction.** The validator only separates score channels. It permits status=VERIFIED with arbitrary attempt_id, mapping_id=None/mapping_version=None, and a verified_score. Cross-record truth and attempt prerequisites are therefore not represented strongly enough to prevent an invalid persisted verified result.
   - Essential fix: VERIFIED construction must be bound to a CONFIRMED mapping/version and a SUCCEEDED frozen attempt. This can be enforced with immutable prerequisite snapshots/typed provenance in EvaluationRecord or through a single validated constructor/service whose preconditions are part of the contract. At minimum, VERIFIED must not allow absent mapping identity/version.
   - A future research-verified channel should also require a versioned research-validation/release identifier; agent or software completion alone must never manufacture scientific verification.

3. **Evaluation workflow state and score-validity channel are conflated.** EvaluationStatus={VERIFIED, EXPERIMENTAL, UNKNOWN} cannot represent evaluator disagreement, needs-review, or evaluator error without collapsing those states into UNKNOWN or forcing a score channel. This conflicts with the required separation of reference state, prediction outcome, evaluation state, and score.
   - Essential fix: split an evaluation-process state (for example COMPLETE / NEEDS_REVIEW / DISAGREEMENT / ERROR) from score status/channel (NONE / EXPERIMENTAL / VERIFIED). Keep ReferenceStatus and AttemptStatus independent.

4. **PredictionManifest does not structurally exclude answer-bearing content because settings is unrestricted.** extra="forbid" blocks unknown top-level fields, but settings: dict[str, Any] can contain reference text, evaluator feedback, retrieval payloads, or other prohibited content and will serialize into the prediction payload. The existing test checks only top-level keys.
   - Essential fix: replace PredictionManifest.settings with a typed, allow-listed, extra-forbid prediction-settings record containing only approved model controls. Do not provide a generic nested escape hatch. Apply the same review to any RunDefinition-to-manifest copy path before Task 4.

5. **FrozenRecord is not deeply immutable.** Pydantic frozen=True prevents attribute reassignment but nested dict values remain mutable. Current mutable nested evidence/configuration includes RedactionTarget.detection_evidence, RunDefinition.settings, PredictionManifest.settings, ModelAttempt.usage, and the dicts inside EvaluationRecord.fact_comparisons. Truth/scoring evidence can therefore change after record creation without creating a new version.
   - Essential fix: use frozen typed submodels and immutable tuples (or an equivalent deep-immutable representation) for persisted provenance/evidence that affects experiment identity or evaluation. EvaluationRecord.fact_comparisons and PredictionManifest settings are the highest-priority cases.

6. **The contract bakes in an unapproved numeric scale.** UnitScore enforces 0.0..1.0 for verified_score and experimental_score. D04 has not approved score mapping, scale, caps, weights, or thresholds. A 0-1 contract is therefore a methodological commitment beyond current research approval.
   - Essential fix: do not make 0-1 the canonical research score scale at Task 1. Keep numeric values nullable and explicitly version the score scale/mapping if an EXPERIMENTAL demo mapping is later approved. Scientific score values remain unavailable until human-adjudicated calibration and research-human approval.

7. **SummarySnapshot is not yet sufficient for the required three-level/fair-denominator semantics.** It has model_id and aggregate counts but no summary level/scope (target vs document vs model), document/target scope identifier, exact eligible/common-set membership, aggregation/formula version, or distinct timeout/malformed accounting. It can also hold a non-null score with eligible_count=0.
   - Essential fix for Task 1 contract: add an explicit summary level and scope identity; preserve exact eligible evaluation IDs/common-set identity and aggregation version; preserve technical outcome counts without silently folding refusal/timeout/malformed/error together; validate zero eligible denominator => null score. Do not invent weights.

8. **Project-scoped referential integrity is not encoded strongly enough to prevent cross-project/stale claims by contract alone.** DocumentVersion has project_id, but mapping/evaluation/summary/run relationship records rely on free-form string IDs without carrying project scope or a declared foreign-key enforcement contract.
   - Essential fix: either carry project_id consistently in relationship records or document/store-test a hard project-scoped referential-integrity invariant before these records can be treated as authoritative. Stable version IDs remain required; hashes alone must never authorize cross-project linkage.

### Positive findings retained

- Non-CONFIRMED ReferenceMapping states cannot expose exact_revealed_text, and the test verifies exact whitespace is preserved for confirmed text.
- UNKNOWN EvaluationRecord requires both score fields to be null; EXPERIMENTAL and VERIFIED numeric channels are separate.
- REFUSED, TIMEOUT, ERROR and MALFORMED are distinct ModelAttempt outcomes, and non-success attempts cannot carry a prediction.
- PredictionManifest forbids extra top-level fields and the current test verifies common reference/evaluation keys are absent at top level.
- RedactionTarget carries target/document versions and normalized geometry.
- Synthetic fixtures are deterministic and include adjacent boxes, repeated anchors, a still-hidden reference, and a selectable hidden-text-layer trap for later leakage testing.

### Synthetic-fixture gap essential to RL-MVP-001

The implementation packet requires partial/ambiguous examples. repeated_anchors covers ambiguity, but still_hidden_reference is fully hidden rather than partially revealed. Add a genuinely PARTIAL reference fixture where only part of one contiguous target is revealed and the remainder remains hidden; its later mapping must remain non-scoreable/null. Wrong-release, conflicting-reference, unreadable-reference, role-reversal and semantic-rubric cases can remain for RL-MVP-003/RL-MVP-005 unless their downstream task explicitly needs them earlier.
