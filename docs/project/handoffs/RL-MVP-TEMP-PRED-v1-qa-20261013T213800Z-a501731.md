## QA/security findings

### Manual-input bounds and marker semantics — PASS

Both helpers enforce:
- string input only;
- nonempty/effective input;
- no NUL;
- valid encodable Unicode / no unpaired UTF-16 surrogate;
- maximum 4,000 UTF-8 bytes;
- exact case-sensitive literal `[REDACTED]`;
- 1–8 markers;
- no `<` or `>`;
- no recognized `javascript ... :` scheme with the reviewed Unicode whitespace/case handling.

No regex/fuzzy marker interpretation can silently turn a different token into a redaction.

The textarea itself is not a persistence or authority boundary; helper validation occurs on generation.

### Deterministic Python / TypeScript behavior — PASS

Candidate phrases are fixed static tuples/arrays and category selection depends only on the immediate ASCII word on either side of each marker, with left cue taking priority.

No randomness, clock, locale, filesystem, browser state, model call or external data is used.

Independent randomized cue probes found no Python/TypeScript category mismatch.

### HTML/script injection safety — PASS

The feature rejects markup-like input as defense in depth.

More importantly, the UI renders errors, basis strings and candidates through ordinary React text nodes. It introduces no `dangerouslySetInnerHTML`, `innerHTML`, document-write or similar HTML sink.

The user-provided demo text remains the controlled textarea value and is not copied into output HTML.

All generated candidate/basis text is static code-owned content.

### No external network / filesystem / persistence effects — PASS

The standalone Python helper is pure and import-free.

The TypeScript helper is pure and has no network/storage API reference.

The React demo uses component memory only. Generate and Clear do not call the existing API, upload, process or persistence functions.
