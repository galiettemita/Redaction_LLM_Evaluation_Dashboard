## Positive findings

### Loopback defaults / redirects / proxies

The default stdlib transport is substantially conservative:
- constructor accepts only exact numeric `http://127.0.0.1:<port>`;
- rejects localhost DNS, IPv6, credentials, path/query/fragment, non-loopback and other schemes;
- default opener installs `ProxyHandler({})` to disable environment proxies;
- redirect handler rejects 30x rather than following it;
- response bytes are capped.

No default-transport non-loopback URL construction was found.

### Durable one-shot worker

The normal public state flow is conservative:
- enqueue scope is unique;
- claim atomically changes PENDING -> IN_DOUBT before dispatch;
- concurrent claim race is protected;
- worker crash/adapter exception after claim leaves IN_DOUBT and no retry path;
- ambiguous TIMEOUT persists a TIMEOUT attempt but leaves job IN_DOUBT;
- reconnect/restart does not select IN_DOUBT rows;
- attempt rows are immutable by SQLite trigger;
- provider result and durable intent request/config provenance are checked before completion;
- duplicate completion cannot create a second attempt because attempts has one row per job.

I found no normal-API duplicate-dispatch path after a successful claim.

### Response outcome semantics

SUCCEEDED, REFUSED, TIMEOUT, ERROR and MALFORMED are represented distinctly. Non-success outcomes do not carry a prediction. Unstructured refusal is intentionally MALFORMED rather than guessed. Timeout is not converted into factual failure/success.

### Redacted-target rendering

For builder-produced manifests, each request preserves one selected TARGET marker and converts all declared other target markers to REDACTED markers. Context budget is consistently enforced using UTF-8 byte length before and after rendering.

## BLOCKING finding 1 — redacted-only trust is not enforced at the worker/manifest boundary

Severity: **Critical / reference-hidden-text leakage**.

The redacted-only guarantee currently depends on caller discipline.

Two independent paths demonstrate the issue:

1. `build_prediction_manifest` accepts a coordinated forged CanonicalRedactedDocument + RunDefinition if both contain a self-consistent forged canonical text/hash/version. The builder proves consistency between caller records, not authority of the canonical text.
2. `RunStore.enqueue` accepts a caller-created PredictionManifest directly, bypassing the builder entirely. Neither the store nor worker recomputes the manifest canonical hash or binds it to a trusted source/canonical record.

A caller can therefore place reference truth, hidden selectable text, previous guesses or evaluator content inside `canonical_redacted_text`, keep the schema structurally valid, and dispatch it through the worker.

This violates the Task-4 requirement that reference/target truth be structurally absent from prediction payloads and that forged canonical input fail closed.

Existing tests only reject a forged canonical text when its hash no longer matches the unchanged RunDefinition. They do not test a coordinated forged doc+run or direct forged-manifest enqueue.

### Required correction

Establish one trusted manifest-construction boundary that the durable store/worker can verify, rather than accepting arbitrary self-consistent caller text.

At minimum add regressions for:
- forged canonical text + recomputed canonical hash + matching forged run hash/version;
- direct forged PredictionManifest enqueue containing answer-bearing/reference text;
- worker refusal to dispatch a manifest that cannot be tied to the trusted canonical source/run identity.

If authoritative source binding requires additional contract/persistence authority, stop and route that scope explicitly rather than assuming caller discipline.

## BLOCKING finding 2 — injected transport bypasses the network-isolation enforcement surface

Severity: **High / egress-control boundary**.

`OllamaAdapter.__init__` accepts an arbitrary `transport` callable. Endpoint validation still validates the configured endpoint string, but when a custom transport is supplied:
- `ProxyHandler({})` is not the mechanism performing I/O;
- `_NoRedirectHandler` is not the mechanism performing I/O;
- the callable may ignore the passed loopback URL;
- the adapter has no enforcement over what network destination, redirect, proxy or protocol that callable uses.

The review packet explicitly requires that injected transport not silently bypass endpoint validation. Current design does not satisfy that as a security boundary.

Mocks are useful for tests, but the injection seam must be explicitly trusted/test-only or wrapped so production egress controls cannot be bypassed by supplying another transport implementation.

Any real external dispatch remains unauthorized; no such call was made in this review.

## BLOCKING finding 3 — successful attempts can be attributed to an unverified model identity

Severity: **High / provenance and experimental-comparability integrity**.

The adapter sends `manifest.model_id` in the request, but the success parser does not verify any provider-returned model identity.

A response envelope can identify `different-model:latest` while containing a valid nested prediction; the current parsing rules still return SUCCEEDED. The worker then persists:
- `attempt.model_id = pending.manifest.model_id`
- `attempt.model_config_id = adapter.model_config_id`

Thus the durable record can assert that the requested model/config produced a response without verifying the provider actually served that model.

For comparative research, requested model identity is not equivalent to verified runtime model provenance.

### Required correction

If the Ollama-compatible response includes model identity/version/digest evidence, validate it against the configured/requested model or fail closed. If the approved protocol cannot verify provider model identity, the stored provenance must not imply stronger model identity than is actually established.

Add a regression where the response names a different model but otherwise contains a valid prediction.

## Nonblocking concerns / limitations

- `common_context_budget` is a UTF-8 byte-length proxy, not a tokenizer/model-context guarantee. This is explicitly documented and acceptable only as an MVP safety proxy; it does not establish cross-model token comparability.
- `RunDefinition.target_versions` is positional rather than target/version keyed. The implementation follows frozen canonical target order and cardinality, but this remains a provenance fragility in the current contract.
- `model_config_id` becomes durable only at claim time and is not part of RunDefinition. A queued run is not pre-bound to a specific adapter configuration before a worker claims it.
- Direct raw SQLite state rewrites can reset COMPLETE/IN_DOUBT to PENDING because state-transition fields are not protected by triggers. Normal RunStore API does not expose this path, so I treat it as hardening risk rather than the primary blocker.
- Real-model feasibility remains BLOCKED per project state. Mock tests do not establish inference quality, model availability, semantic accuracy, D03 validity or production behavior.
