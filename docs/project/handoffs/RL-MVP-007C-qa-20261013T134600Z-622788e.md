## QA/security findings

### Frozen API contract handling — PASS

`web/src/api.ts` validates the v0.1 API header, JSON media type, required response identities and expected enums before exposing responses to UI state.

It rejects:
- API-version mismatch;
- malformed JSON;
- non-string health/result enum values;
- mismatched document/job identities;
- malformed metadata;
- fabricated targets;
- non-null summaries;
- non-null numeric scores;
- promoted reference truth.

Relative same-origin GET/POST routes match frozen API v0.1. No undocumented prediction or scoring route was added.

### Unsafe response rendering — PASS

The React source renders values through normal JSX/text nodes and uses no raw-HTML sink.

Raw server `error.message` is intentionally ignored. `ApiError` messages shown in the UI are fixed local strings chosen from code/status mappings.

Document/job IDs and SHA/status data come through strict adapter validation before rendering. No demonstrated XSS or arbitrary navigation path was found.

### Upload handling — PASS

Client-side checks enforce:
- required redacted file;
- optional reference;
- PDF extension/MIME consistency;
- nonempty file;
- 25 MiB/file maximum;
- bounded project ID.

The frontend does not claim browser validation is authority: the server remains responsible for signature, multipart and pair bounds.

Uploads use `FormData` without manually setting multipart Content-Type, avoiding broken boundary handling.

No upload is sent to an external origin.

### Redirect / network isolation — PASS

`createApi(window.location.origin)` accepts only literal `127.0.0.1` HTTP/HTTPS origin with root path and no credentials/query/hash.

Fetch uses relative paths and `redirect:"error"`. A redirect cannot silently send document data to another site.

### Error, stale-state and reconnect behavior — PASS

Reconnect/refresh performs GET-only status recovery; it does not replay upload or process POSTs.

A failed refresh clears the previous snapshot before surfacing an error, avoiding stale state appearing current.

Write failures are not automatically retried.

### Truth / score presentation — PASS

The UI explicitly states:
- adding a reference does not establish trustworthy truth;
- accuracy is unknown;
- per-redaction/document/model scores are unavailable;
- no verified/experimental score exists;
- processing failure is not an incorrect prediction;
- READY/AVAILABLE document state is not presented as prediction success.

`NEEDS_REVIEW` remains a distinct state.

No browser calculation converts null/unknown to zero.

### Reference isolation — PASS

Reference upload is optional and only the receipt's existence/opaque ID is retained in component state.

Reference bytes/text are not stored in localStorage, used for prediction, rendered as truth or sent to another route.

The adapter refuses any result payload that promotes `truth_status` beyond `UNKNOWN`.
