## Four prior blockers — fresh resolution assessment

### 1. Project-scoped target identity — RESOLVED

Corrected identity material now includes `project_id`, document-version ID, page, normalized geometry and detector version, encoded using JSON rather than delimiter joining. Independent probes confirmed:
- same document/page/bbox under different projects -> distinct target IDs;
- delimiter-bearing pairs such as `("a|b","c")` versus `("a","b|c")` -> distinct target IDs.

This resolves the prior cross-project/delimiter ambiguity for the reviewed identity formula.

### 2. Ambiguous multi-column reading order — PARTIALLY RESOLVED, STILL BLOCKING

The corrected helper rejects the routed wide, narrow-gutter and staggered multi-line column cases, and an ordinary single-column probe did not trigger a false positive.

However, the algorithm only recognizes a column start when that spatial start repeats on at least two segmented lines (`count >= 2`). A two-column page with one line in each column produces two spatial spans but neither start repeats. Independent execution of the exact helper returned:
`multicolumn one-line: False`.

There is no later layout check before canonicalization that rejects this case. Such a page can therefore proceed to the existing canonicalizer, which orders same-line positioned text by x coordinate and can interleave left/right column context. The corrected review packet requires two-column/ambiguous positioned-text layouts to fail closed rather than interleave text; it does not limit that requirement to columns with two or more lines.

Reproducible minimal condition:
- one left-column text line near x=72;
- one right-column text line near x=330 on the same baseline;
- ordinary near-black redaction overlay covering extractable text in one column;
- no images, annotations, transforms, line art or other unsupported operators.

The current `_has_ambiguous_multicolumn_layout` returns False because both column-start clusters have count 1.

**Required correction:** reject ambiguous one-line/two-block spatial layouts when they can affect canonical reading order, or establish another conservative layout rule that proves the page is single-flow before emitting canonical text. Add a one-line two-column regression plus a legitimate single-line/single-column negative control.

### 3. Overlapping / duplicate redaction rectangles — RESOLVED for the routed cases

The corrected detector first restricts overlap analysis to rectangles related to text by intersection, same-line flow or near-text-block evidence, then rejects intersecting pairs with reason `OVERLAPPING_REDACTION_RECTANGLES`.

Independent probes confirmed:
- overlapping text-related boxes trigger the overlap predicate;
- adjacent non-overlapping boxes do not;
- overlapping remote artwork remains outside the text-related set and can still be ignored rather than causing a false unsupported result.

The existing corrected tests also cover exact duplicates and adjacent boxes.

### 4. Standalone ambiguous black rectangle — RESOLVED for the routed cases

`_near_text_block` now treats a rectangle as text-related when it horizontally aligns with nearby text or lies between visible text above and below in the same horizontal band, rather than silently classifying all no-glyph/no-same-line rectangles as artwork.

Independent probes confirmed:
- a standalone redaction-shaped rectangle inside a text column between visible content is classified as near-text ambiguity;
- a remote black artwork rectangle outside the text band is not.

This closes the prior false `NO_REDACTIONS` path for the routed standalone cases while retaining a remote-artwork path.
