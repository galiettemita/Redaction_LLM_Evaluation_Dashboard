## Blocking finding

### IMPORTANT — verified runtime may accept a fully substituted model identity, then persist an unusable frozen run before dispatch fails

**Observed source path**

`InferenceRuntime.verified()` requires only that:
- `model_id == provider_model_id`;
- model manifest/executable/model-store hashes and API identity match the lock.

It does **not** require the lock's model name to equal the E0065 approved run model constant:
`qwen2.5:1.5b-instruct-q4_K_M`.

`PredictionService.run()` then:
1. verifies the runtime;
2. builds a run using hardcoded `MODEL_ID = qwen2.5:1.5b-instruct-q4_K_M`;
3. persists missing target intents;
4. dispatches them.

The Ollama adapter rejects only at request preparation when `manifest.model_id != adapter.model_id`.

Therefore a lock where **both** `model_id` and `provider_model_id` are consistently changed to another otherwise-valid model can survive runtime verification. PredictionService can then persist the deterministic qwen run/intents before the first dispatch raises `manifest model does not match adapter model`.

This is fail-closed with respect to external inference, but it is **not fail-before-mutation** and can freeze durable PENDING intents to a runtime identity that cannot later be resumed by a corrected runtime with different model config/manifest digest.

**Exact-source independent probe**

Assertions against exact SHA `e6669c2` confirmed:
- runtime only compares lock `model_id` to lock `provider_model_id`;
- inference runtime contains no approved qwen model constant;
- PredictionService hardcodes qwen in the RunDefinition;
- no adapter-model equality check exists between runtime verification and enqueue;
- intents are enqueued before dispatch;
- OllamaAdapter later rejects manifest/adapter model mismatch.

Result: **6/6 relevant source-order/security assertions PASS**, demonstrating the defect path.

**Independent adversarial reproduction**

A standalone state-order reproduction modeled the exact verified/enqueue/prepare sequence:
- substituted lock model == substituted provider model;
- two target intents persisted under hardcoded qwen run;
- adapter request preparation rejected qwen vs substituted runtime model;
- both durable intents remained PENDING.

Result: **PASS — defect reproduced**.

This reproduction is source-level and does not claim execution of the repository package.

**Minimal correction**

Before `_run_definition()` or any `RunStore.enqueue()` mutation, require the verified runtime's model identity to equal the approved `MODEL_ID`.

Minimal implementation shape:
- expose/use `verified.adapter.model_id`;
- immediately after `InferenceRuntime().verified()`, reject unless `verified.adapter.model_id == MODEL_ID`;
- perform this check before any run/intents are constructed or persisted.

Add an adversarial test where both runtime-lock `model_id` and `provider_model_id` are changed to the same substitute model, with otherwise valid hashes/API identity, and assert:
1. service fails closed **before mutation**;
2. zero Task-4 jobs/intents are created;
3. a later corrected runtime can still create the intended run.

Optionally include the exact model identity in the explicit runtime identity payload (`created_by`) so the frozen runtime identity is self-describing rather than inferred only from RunDefinition + config/digest.
