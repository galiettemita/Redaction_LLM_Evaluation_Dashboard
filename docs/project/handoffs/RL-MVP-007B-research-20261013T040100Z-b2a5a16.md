## Research findings

### 1. Reference isolation — PASS

The API accepts an optional reference PDF only as a role-separated upload. The upload response explicitly returns `truth_status:"UNKNOWN"`.

The 7B API does not import or invoke Task-3 reference alignment, DEC-022 fixture registration, EvaluationStore, evaluator code, or any reference-trust authority.

Reference versions are rejected by the results route with `RESULTS_UNAVAILABLE`; no prediction result is exposed for a reference role.

No reference content is added to Task-4 PredictionSource or PredictionManifest paths.

Therefore an uploaded or paired reference does not gain trusted-truth status and does not enter prediction input.

### 2. No unauthorized source or prediction authority — PASS

The API composes only the integrated application services and production `DocumentWorker(self.store, self.artifacts)`.

Exact-source inspection found:
- no `EvaluationStore` import;
- no reference aligner/trusted-fixture invocation;
- no `.enqueue(...)`, `run_pending_once`, PredictionAdapter or ModelAttempt creation in the new API package.

Processing therefore validates/derives document state through the existing application-owned worker path but does **not** enqueue or run a Task-4 model prediction.

The API adds no caller-supplied worker, source, source-material, source-deriver or trusted flag.

### 3. Unverified runtime fails closed before Task-4 source authority — PASS

The frozen API contract requires a 503 while the PDF runtime is unqualified.

The reviewed route invokes the production `DocumentWorker`, whose integrated 7A behavior verifies the install-owned runtime before claiming work.

Candidate tests show the shipped unverified or missing runtime returns:

`503 RUNTIME_UNVERIFIED`

while the application job remains `ACCEPTED`, owner remains null and Task-4 canonical-source count is unchanged.

This prevents API presence alone from fabricating PDF-derived Task-4 authority.

### 4. Task-4 immutable / one-shot semantics remain unchanged — PASS

7B does not modify Task-4 source identity, enqueue, claim, retry, attempt, timeout or immutable-record code.

The process endpoint does not enqueue prediction work. It also refuses to process a later queued document ahead of the earliest accepted application job.

No hidden retry or reconnect-to-new-prediction behavior is introduced.

### 5. DEC-022 remains synthetic-only — PASS

The API contract and implementation expose upload truth as `UNKNOWN`.

No arbitrary reference upload can produce `APPROVED_SYNTHETIC_PAIR`, a ReferenceMapping, or scoreable truth through these routes.

The API therefore does not broaden DEC-022.

### 6. Task-6 evidence remains immutable and unexposed as verified accuracy — PASS

The new API does not import or mutate Task-6 evaluation or summary stores.

The results route is deliberately conservative:
- `targets: []`
- `summaries: {target:null, document:null, model:null}`
- `score_status:"NONE"`
- `verified_score:null`
- `experimental_score:null`
- `truth_status:"UNKNOWN"`

It does not synthesize a target result, evaluator judgment or score from upload/job state.

### 7. NEEDS_REVIEW semantics remain intact — PASS

The integrated Task-6 evaluator remains unchanged at this candidate SHA:
- missing frozen source-fact record -> `NEEDS_REVIEW`;
- mock/source-fact judgments remain `UNVALIDATED_SYNTHETIC`;
- mock evidence remains `UNVALIDATED_MOCK_EVIDENCE`;
- no numeric score is produced.

7B creates no alternate API route that upgrades those states to verified accuracy.

### 8. Processing terminal states remain distinct from semantic accuracy — PASS

The API maps application processing states to `PENDING`, `NO_REDACTIONS`, `UNSUPPORTED`, `FAILED`, or contract-defined `AVAILABLE`, while keeping targets empty, summaries null, scores null and truth unknown.

Thus parser/job state is not converted into semantic factual accuracy.

The contract-defined `AVAILABLE` state after a READY document should be understood as document-processing availability only; this candidate does not present evaluated reconstruction evidence behind it.
