## Correction-02 blocker — independent application-process startup race

**RESOLVED.**

The candidate adds a persistent database-specific sibling lock:

`.redaction-lab-migration-<sha256(database-basename)>.lock`

under the already verified database-directory descriptor.

The lock is acquired before:
- database leaf inspection/open;
- backup-directory creation/open;
- incomplete `.part` cleanup;
- migration-state inspection;
- backup creation;
- helper invocation.

A second cooperating Redaction Lab process therefore waits on the same database-specific kernel flock, then reopens/rechecks migration state only after the winner has completed.

The exact candidate test is a real two-independent-process test with explicit readiness/IPC rather than arbitrary sleep. It requires:
- both processes to succeed;
- applied-version results to partition exactly as `()` and `(1,)`;
- exactly one migration row;
- exactly one final backup;
- no residual `.part`;
- preexisting legacy payload preserved.

Source review matches that intended serialization.

**PASS.**

- `sys.executable`;
- `shell=False`;
- `cwd=None`;
- `close_fds=True`;
- exact four-descriptor `pass_fds`: database directory, database leaf, backup directory and migration lock;
- no `preexec_fn`.

- requires four distinct FDs;
