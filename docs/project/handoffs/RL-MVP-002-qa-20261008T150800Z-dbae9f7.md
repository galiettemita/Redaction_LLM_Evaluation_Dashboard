## Previously blocking case 1 — staggered one-line columns

### PARTIALLY FIXED, STILL BLOCKING

Correction 03 adds `staggered_sparse_columns`, which rejects horizontally disjoint one-line blocks when their starts are column-separated and their baseline/top separation is no more than:

`max(48.0, max(first_height, second_height) * 4.0)`

This catches the Backend regression at roughly 40 pt vertical separation.

However, the exact helper still returns **False** for the same two-column geometry at 49, 60 and 80 pt vertical separation. In those cases:
- each line still has a single span;
- no column start repeats;
- `split_line` is false;
- `sparse_secondary_column` is false;
- the fixed 48 pt vertical-window condition makes `staggered_sparse_columns` false.

The Correction 03 review packet explicitly requires staggered one-line columns at different baselines and varying separation to fail closed when single reading order cannot be proven. A two-column page does not become safely single-flow merely because the two isolated column lines are 49+ points apart.

**Blocking reproduction:** left text around x=72 and right text around x=330, one line each, ordinary black text, supported black overlay in one block, with baseline separation 49+ pt. Current v4 helper does not mark layout ambiguous.

Required correction: do not use a narrow vertical-distance cutoff as proof of single reading flow for two isolated horizontally separated spans. Either establish stronger single-flow evidence or fail closed for the sparse positioned case.

## Previously blocking case 2 — near / indented standalone no-glyph redaction boxes

### PARTIALLY FIXED, STILL BLOCKING

Correction 03 broadens `_aligned_with_text_block` beyond literal x-overlap. For a text-like rectangle with no occluded characters it now accepts horizontal proximity up to:

`max(36.0, rectangle_width * 1.5)`

For the 120 pt-wide routed rectangle this is a 180 pt maximum gap. This correctly catches the Backend tests around x=105 and x=260 next to a short visible line beginning at x=72.

But the classification still flips to "artwork" at a hard horizontal threshold. With an actual ReportLab/pdfplumber "Short" line at x≈72..98.29:
- a 120 pt-wide no-glyph box starting at x=260 is ambiguous -> **True**;
- the same plausible text-sized boundary box at x=280 is ambiguous -> **False**;
- x=300 is also **False**.

For x=280, there are no occluded chars, no same-line visible neighbors and `_aligned_with_text_block` returns false; the current detector then follows the ignored-artwork branch and can return `NO_REDACTIONS`.

The Correction 03 packet requires near/indented/moderately offset one-sided boundary boxes to require affirmative evidence before dismissal as artwork. A ~20 pt shift beyond the routed x=260 test does not establish that a text-sized black rectangle in the document's general text region is decorative artwork.

**Blocking reproduction:** short visible line near x=72..98, no-glyph 120x14 black box above/below starting around x=280. Current v4 proximity rule treats it as non-text/ignorable.

Required correction: use page/text-region evidence that distinguishes plausible boundary redaction geometry from confidently remote art, rather than a single width-scaled horizontal cutoff that can silently convert an unresolved case to `NO_REDACTIONS`.

## New regression — legitimate short centered heading can be rejected as multi-column

### HIGH / BLOCKING REGRESSION

The v4 sparse-column rule also creates a false positive for a legitimate single-column heading/body layout.

Independent probe:
- short centered heading "Title" at x≈300, 16 pt font;
- ordinary body line at x≈72, 11 pt font;
- vertical separation around 44 pt.

The exact v4 helper returns `AMBIGUOUS_TEXT_LAYOUT=True` because:
- the two spans are horizontally disjoint;
- their starts are separated by more than 15% of page width;
- vertical/top difference is below the 48 pt cutoff.

The Correction 03 review packet explicitly requires checking headings and legitimate single-column layouts. Backend's heading negative control uses a longer centered heading whose x-range overlaps the body line, so it does not exercise this shorter-heading case.

This is fail-closed rather than leakage, but it is a regression against the accepted week-one single-column class and the routed negative-control requirement.

Required correction: ensure short centered/indented heading + body patterns are not classified as columns solely because two disjoint spans are horizontally separated and close vertically, while still rejecting actual sparse two-column layouts.
