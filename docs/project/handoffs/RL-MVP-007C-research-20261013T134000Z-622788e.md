## Research findings

### Truth and score presentation — PASS

The frontend consumes frozen API v0.1 and fails closed unless result payloads retain:
- `truth_status === "UNKNOWN"`;
- `score_status === "NONE"`;
- `verified_score === null`;
- `experimental_score === null`;
- empty `targets`;
- null target/document/model summaries.

`presentResults` renders all states as unknown/non-scored and never maps null to zero. `NEEDS_REVIEW` is explicitly displayed as “Needs review” with predictions/scores unavailable. `FAILED` explicitly says a processing failure is not an incorrect prediction. `AVAILABLE` says only that document processing completed and that the API does not yet supply passage predictions/evaluation summaries.

This preserves DEC-004 and Task-6 null-score semantics.

### Reference isolation — PASS

The reference input is optional and the UI explicitly states: “Adding a reference does not establish trustworthy revealed text or verified accuracy.”

The client accepts an upload receipt only when `truth_status === "UNKNOWN"`; it exposes no route or local calculation that upgrades reference trust.

No reference content is written to browser storage. Browser storage retains only opaque document/job recovery IDs.

No Task-3 alignment, DEC-022 fixture enrollment, scoring or evaluator route exists in the frontend.

### No fabricated predictions / semantic completion — PASS

The UI presents:
- no target text;
- no passage reconstruction;
- no model ranking;
- no target/document/model score;
- no browser-derived accuracy.

Document readiness is explicitly separated from prediction success. The interface states that preview cannot establish targets or revealed truth.

### Refresh/recovery semantics — PASS

Refresh and recovery issue GET-only status reads and do not replay upload/process actions. Failed refresh clears the previous snapshot rather than presenting stale results as current.

This does not weaken Task-4 one-shot/no-hidden-retry semantics.
